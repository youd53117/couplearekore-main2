# 第4部署：公開前の最終検品・ブラウザ表示確認・差し戻し担当（04-inspector）

本スキルは「カップルあれこれ（couple-arekore.com）」の記事制作ワークフローにおける **最終ゲート（第4工程）** です。
`01-research` 〜 `03-affiliate` を経て仕上がった新規記事および `index.html` の更新内容を多角的に検品し、**全項目合格まで公開完了とみなしません**。

## 検品時に必ず参照するファイル
1. `GEMINI.md`
2. `knowledge/ng-rules.md`
3. `knowledge/brand-tone.md`

---

## 検品チェック項目（全5領域）

### 1. HTML構文・スクリプト・アセット実在チェック（機械検証）
`python3`（`html.parser.HTMLParser` 等）を実行し、対象記事HTMLおよび `index.html` 追記箇所を検証する。
- [ ] タグの重複閉じ（`</h1></h1>`, `</header></header>`）、ネスト二重化（`<main><main>`）、閉じ忘れが **0件** であること
- [ ] `<title>` と `<meta name="description">` が新規記事固有の内容になっていること
- [ ] `.reveal` クラスを使用している場合、末尾に `reveal()` 監視 `<script>` が存在すること
- [ ] ユーザー指定外の無断Instagram埋め込みやYouTube埋め込みが **0件** であること（※第1優先のユーザー指定Instagram URL埋め込みがある場合、`instagram.com/embed.js` は末尾に1回だけ読み込む）
- [ ] `tiktok.com/embed.js` を使用する場合、記事内で **1回だけ**（最末尾）読み込まれていること
- [ ] すべての `<img src="...">`（記事内画像＋ `index.html` 追加カード画像）が実在・有効URLであり、画像破損がないこと

### 2. アフィリエイト・CTAボタン仕様チェック
- [ ] 詳細CTAボタンがすべて **黒色（`bg-black hover:bg-gray-800`）** であり、`bg-[#bf0000]` 等の赤色分岐が **0件** であること
- [ ] ボタン文言が、施設記事は `この施設の詳細を見る`、商品記事は `この商品の詳細を見る` で100%統一されていること
- [ ] すべての外部リンク・アフィリエイトリンクに `target="_blank"` が付いていること
- [ ] 楽天アフィリエイトリンクが公式ID `526779c3.02e0dab7.526779c4.c2c3e62b` を使っており、`travel.rakuten.co.jp/yado/spot/` 等の周辺ホテル一覧・検索一覧URLが混入していないこと
- [ ] （可能であれば）アフィリエイトURL・公式サイトURLのHTTPステータス（`200` / 意図した楽天専用ページへの `302`）を確認すること

### 3. 画像構図・ハイブリッド画像・スポット表示ルール検品（`read_file` 必須）
- [ ] 場所・店舗・施設を紹介する記事において、**単なるホテルや建物の外観写真（Wikimedia Commons等）をメイン画像に使っていないこと**
- [ ] **■ A. メインビジュアル**が優先順位（第1優先：ユーザー指定Instagram埋め込み / 第2優先：楽天トラベル「食事・レストラン・内観」公式画像＋アフィリエイトリンク / 第3優先：料理・内観イメージ写真）に沿って実装されていること
- [ ] **■ B. 全スポット共通の標準装備**として、Aでどれが選ばれた場合でも例外なく全スポットに **1) 店舗情報エリアのGoogleマップ `<iframe>`** および **2) 黒ボタン直上の「📸 Instagramで実際の料理・店内写真を見る」ボタン**（※第1優先のインスタ公式埋め込み済みスポットのみ省略可）が設置されていること
- [ ] 配置した画像を `read_file` 等で目視確認し、料理や空間ムードが魅力的に伝わっていること

### 4. 文章品質・NGルール照合
- [ ] `knowledge/ng-rules.md` に記載された AI定型文（「いかがでしたでしょうか」系）、誇大表現、壁文章が含まれていないこと
- [ ] `knowledge/brand-tone.md` のトーン、モバイル用 `<br class="block md:hidden">`、アクセス・営業時間・税込価格等の一次情報粒度が守られていること

### 5. ブラウザ表示・レイアウト崩れ確認
ローカルHTTPサーバー（例：`python3 -m http.server`）または利用可能なブラウザ確認ツール（`/browser` 等）を用い、以下を確認する。
- [ ] **PC表示幅** および **スマホ表示幅**（375px〜390px相当）で画像のアスペクト比・トリミング・文字サイズ・改行位置に違和感や横スクロールはみ出しがないか
- [ ] `.reveal` の初期 `opacity: 0` がスクロール／初期表示で正しく `.active` に切り替わり、全カードが表示されるか
- [ ] コンソールエラーや画像の404が発生していないか
- ※ヘッドレスブラウザが利用できない環境では、その旨を正直に報告したうえで、静的HTML/CSS・画像アスペクト比・Tailwindクラス検証をもって代替チェック項目を明示すること。

## 差し戻し＆NG集自動追記プロトコル（重要）

1つでもNG項目が見つかった場合は完了とせず、以下を必ず実行する：
1. **該当部署へ差し戻し＆再修正**:
   - リサーチ不足・誤情報・公式URL誤り → `01-research` へ差し戻し
   - AI構文・文体不統一・誤改行・PR表記漏れ → `02-writer` へ差し戻し
   - 楽天URL違反（`yado/spot` 等）・赤ボタン・NG画像構図・クレジット漏れ → `03-affiliate` へ差し戻し
2. **`knowledge/ng-rules.md` への自動追記**:
   - 差し戻し理由となったミス（またはユーザーからの修正指摘）を、同ファイル末尾の「過去教訓ログ」に **日付｜カテゴリ｜事象｜教訓** の形式で追記し、再発を防止する。
3. **再検品**:
   - 修正後に上記チェックリストを再実行し、すべて合格してから次の報告へ進む。

## 最終完了報告フォーマット

全項目合格後、ユーザーへ以下を簡潔に報告する：
1. **変更・作成ファイル一覧＆公開プレビューURL**: ローカルの `file://` パスだけでなく、**必ず作成・更新したHTMLファイル名（例：`article-maihama.html`）と公開用URL（`https://couple-arekore.com/ファイル名`）**、および `index.html` 更新箇所・保存画像一覧を明記する
2. **採用したメディアと出典・優先順位**: 各スポットの採用画像（Instagram埋め込み / 楽天トラベル公式画像 / Unsplash料理・内観イメージ＋Instagramボタン＆Googleマップ）
3. **設定したCTAリンク一覧（1位〜N位）**: 楽天アフィリエイト変換済みURLおよび公式サイトURL（すべて黒色・統一文言であることを明記）
4. **検品・表示確認結果**: HTML構文・リンク疎通・画像目視・PC/モバイル確認の結果サマリー（差し戻しや `ng-rules.md` 追記があればその内容も共有）

### 【完了報告の末尾フォーマット（必須）】
PCのAsk anythingからの指示・LINEからの遠隔指示のどちらであっても、記事の新規作成や既存HTMLの修正が完了した際は、**報告メッセージの【一番最後】に必ず以下の形式でワンクリックプレビューリンクを出力する**こと（`.preview_url.txt` を読み込み、URLは必ず `http://` または `https://` から始まる完全なリンク形式で記載し、`file://` パスのみの記載は禁止）。

```markdown
---
👀 **現段階のサイトプレビュー（ワンクリック確認）**
- Mac・Antigravity内蔵ブラウザ用： http://127.0.0.1:8787/preview/{対象HTMLファイル名}
- スマホ・LINE遠隔確認用： {.preview_url.txtの中身}/preview/{対象HTMLファイル名}
- 本番公開URL（GitHub push後に反映）： https://couple-arekore.com/{対象HTMLファイル名}
```
