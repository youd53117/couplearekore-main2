# 記事作成スキル（create-article）

このスキルは、プロジェクトルートの `GEMINI.md` に定義されたデザインルール・HTML構成・メディア規約・楽天アフィリエイトルールに従って、「カップルあれこれ | 公式Webマガジン」に新しい記事ページを追加し、`index.html` へリンクカードを組み込むための一連のワークフローです。

## 実行前の前提確認

作業開始前に、以下のファイルを必ず確認すること。
1. `GEMINI.md`: 共通 `<head>`、Tailwind設定、カラー・タイポグラフィ、3パターン構造、楽天アフィリエイトID（`hgc/`）および変換ルール、メディア取得ルール、品質チェックリスト
2. `index.html`: 既存カードの記述形式とセクション構造（`#gift` / `#date`）
3. 選択パターンに対応する既存記事ファイル:
   - **パターンA（ギフト・アイテムまとめ型）**: `article-perfume5.html`
   - **パターンB（デートスポットランキング型）**: `article-yokohama.html` / `article-tokyo.html` / `article-nagoya.html`
   - **パターンC（単体アイテム深掘りレビュー型）**: `article-aliba.html`

## ステップ1: テーマと対象パターンの確定

ユーザーから以下の情報を受け取る（不足している場合は質問して確認する）。
- **テーマ**: 例「横浜のカップルにおすすめのデートスポット5選」「記念日ギフト5選」
- **対象パターン**: `A`（ギフト・アイテムまとめ型）/ `B`（デートスポットランキング型）/ `C`（単体アイテム深掘りレビュー型）
- **ファイル名（スラッグ）**: `article-<slug>.html`（半角英数字・ハイフン、例: `article-kyoto.html`, `article-watch5.html`）
- **掲載年月・サブカテゴリ**: 例 `2026.11 / Yokohama Date`

## ステップ2: 最新情報・楽天URL・著作権クリア写真の自動リサーチ＆取得

掲載する各スポット・商品の最新情報、アフィリエイト対象URL、および著作権フリー写真を以下の手順でリサーチ・取得する。

### 2.1 スポット・商品情報のWeb検索
`search_web` 等を使用し、以下を調査する。
- 正式名称・住所・アクセス（最寄り駅からの徒歩分数など）
- 最新営業時間・定休日・料金・価格帯（税込）・カップルにおすすめのポイント
- 公式サイトURL

### 2.2 楽天系URLの検索＆アフィリエイトリンク自動生成（適用条件の厳格化）
ボタンのリンク先は、**「その施設・商品そのものの専用ページ」が楽天に存在する場合に限り**楽天アフィリエイトリンクを優先し、`GEMINI.md` に記録された `hgc/` ID を用いて **エージェント自身がURLエンコード変換を自動実行** する。

1. **楽天の「専用ページ」の有無を厳格に確認**:
   - **変換対象になる例（専用ページあり）**:
     - ギフト・商品の場合（パターンA / C）: 楽天市場（`item.rakuten.co.jp`）の該当商品個別ページ
     - デートスポット・施設の場合（パターンB）: 楽天トラベル観光体験（`experiences.travel.rakuten.co.jp`）の入場チケット・体験プラン専用ページ（例: YOKOHAMA AIR CABIN）、または宿泊施設・ホテルそのものの予約ページ（`travel.rakuten.co.jp/HOTEL/...`）
   - **変換禁止（周辺検索一覧・スポット概要ページ）**:
     - 赤レンガ倉庫や大さん橋などの観光施設で、楽天側に専用の体験チケット・施設予約ページがなく、`travel.rakuten.co.jp/yado/spot/...` のような「周辺ホテルの検索結果一覧」や検索一覧ページしか存在しない場合は、**無理に楽天アフィリエイトを使わず、必ずその施設の「公式サイトURL」をそのまま採用する**。
2. **楽天アフィリエイトURLへ自動変換（専用ページがある場合のみ）**:
   - `GEMINI.md` に記録された公式楽天アフィリエイトID `526779c3.02e0dab7.526779c4.c2c3e62b` を使用する。
   - 変換フォーマット（対象URLをUTF-8でURLエンコードして `pc=` に渡す）:
     ```
     https://hb.afl.rakuten.co.jp/hgc/526779c3.02e0dab7.526779c4.c2c3e62b/?pc=<URL_ENCODED_RAKUTEN_URL>
     ```
   - 変換したURLは可能であればHTTPレスポンス（302リダイレクト先が意図した楽天専用ページであること）を確認する。

### 2.3 著作権クリア写真（Wikimedia Commons等）の検索・厳選・ダウンロード＆リサイズ
Instagram埋め込み（ログイン制限でプレビュー不可になる恐れがあるため**使用禁止**）は使わず、以下の優先順位で各スポット・商品のメディアおよび `index.html` 用サムネイルを用意する。

1. **第1優先: Wikimedia Commons（ウィキメディア・コモンズ）から象徴的な実物写真を厳選取得**
   - `commons.wikimedia.org` の MediaWiki API（`action=query&list=search` / `generator=categorymembers` / `prop=imageinfo&iiprop=url|size|extmetadata`）等で該当スポット・商品・エリアの著作権フリー写真（`CC0` / `Public Domain` / `CC BY` / `CC BY-SA` 等）を検索する。
   - **ライセンス確認**:
     - `CC BY` / `CC BY-SA` の場合はクレジット表記用の `Artist` と `LicenseShortName` を必ず控える。
     - `CC BY-NC` や `ND` 等、商用不可・改変不可ライセンスは避ける。
   - **写真選定・品質チェック基準（重要）**:
     - **単に検索トップの1枚をそのまま使うことは禁止。必ず複数の候補画像をダウンロードして `read_file` で目視比較すること。**
     - **採用基準**: 「その施設の象徴的な外観や建築全体がしっかり映っていて、読者がパッと見た瞬間に『あ、この施設だ』と一目で分かる映える構図の写真」だけを厳選する。
     - **NG例**: デッキや床・壁の一部だけを切り取った写真、看板や案内板のアップ、遠くから小さくしか映っておらず施設と判別しづらい写真。
   - 厳選した画像はルート直下に半角英数字・ハイフン名（例: `yokohama-akarenga.jpg`）で保存し、記事内表示用に横幅1280px程度へリサイズする。
2. **トップページ（`index.html`）用サムネイル（1:1正方形）の取得・生成**
   - `#date` カード等で使用する `1:1`（`1080x1080` 等）サムネイルも、Wikimedia Commons 等からエリア・テーマを代表する実物写真をダウンロードし、`sips` 等で中央正方形クロップ＆リサイズしてルート直下に保存する（例: `yokohama.jpg`）。
3. **第2優先（Wikimedia Commonsで適切な写真が見つからない場合のフォールバック）**:
   - **デートスポット（パターンB）の場合**: そのスポットの **Googleマップ公式埋め込み（`<iframe>`）** を配置する。
   - **商品・ギフト（パターンA / C）の場合**: **楽天アフィリエイトの画像付きリンクタグ（または商品公式ページの許可画像＋出典表記）** を配置する。

## ステップ3: 新しい記事HTMLファイルの作成

`GEMINI.md` の該当パターンおよび参考記事をベースに、ルートディレクトリへ `article-<slug>.html` を作成する。

### 3.1 作成時の厳守ルール
1. **`<head>` の共通化とメタ情報の固有化**:
   - `GEMINI.md` セクション2のCDN（Tailwind Play CDN、Google Fonts 4種、FontAwesome 6.4.0）と `tailwind.config`、`<style>` をそのまま使用する。
   - `<title>記事タイトル | カップルあれこれ 公式Webマガジン</title>` と `<meta name="description" content="...">` を記事固有の内容へ書き換える。
2. **共通ナビゲーション＆PR表記**:
   - ロゴリンクは `href="index.html"` にする。
   - PR表記を必ず入れる（ギフト: `※本記事にはアフィリエイト広告（PR）が含まれています。` / デート: `※本ページはプロモーションが含まれています`）。
3. **メディアの配置（著作権クリア・動画/Instagram不使用）**:
   - **Wikimedia Commons写真がある場合**:
     - カード上部に `<img src="ファイル名.jpg" alt="スポット名・説明" class="w-full h-64 md:h-96 object-cover bg-gray-100">`（全体表示が適する場合は `object-contain`）を配置する。
     - `CC BY` / `CC BY-SA` 等クレジット表記が必要なライセンス（またはクレジット推奨）の場合は、画像直下に控えめなキャプションを記載する:
       ```html
       <p class="text-[11px] text-gray-400 text-right px-6 pt-2">写真：著者名 / Wikimedia Commons (ライセンス名)</p>
       ```
   - **フォールバック（Googleマップ公式埋め込み）**:
     ```html
     <div class="w-full h-72 md:h-96 bg-gray-100 border-b border-gray-200">
         <iframe src="https://maps.google.com/maps?q=スポット名&output=embed" class="w-full h-full border-0" loading="lazy" allowfullscreen="" referrerpolicy="no-referrer-when-downgrade"></iframe>
     </div>
     ```
   - **Instagram埋め込みやYouTube埋め込みは配置しない。**
4. **詳細ボタンのリンク先・文言・カラー（黒色）の完全統一**:
   - **文言の厳格統一**:
     - デートスポット・施設記事（パターンB）: リンク先が楽天・公式のいずれであっても **必ず `この施設の詳細を見る`** に統一する。
     - 商品・ギフト記事（パターンA / C）: リンク先が楽天・公式のいずれであっても **必ず `この商品の詳細を見る`** に統一する。
   - **ボタンスタイル（黒色 `#111111` ベース完全統一）**:
     - リンク先が楽天アフィリエイト（`hb.afl.rakuten.co.jp/hgc/...`）であっても公式サイトであっても、ボタンはすべてサイト基本カラーの黒（`bg-black hover:bg-gray-800`）に統一する。赤色など別の色に分けることは禁止する：
       `block w-full bg-black hover:bg-gray-800 text-white text-center font-bold py-4 rounded-lg transition shadow-sm text-lg`
   - 外部リンクにはすべて `target="_blank" rel="noopener noreferrer"`（または `target="_blank"`）を付与する。
5. **モバイル最適化とアニメーションJS**:
   - スマホ・PCで不自然な改行が起きないよう `<br class="block md:hidden">` / `<br class="hidden md:block">` を使い分ける。
   - パターンB等で `.reveal` クラスを使う場合は、ページ末尾に IntersectionObserver ベースの `.reveal` 監視 `<script>` を必ず配置する。

## ステップ4: `index.html` へのリンクカード追記

記事の種別に応じて `index.html` に新しいリンクカードを追加する。

- **パターンA / C（GIFT・REVIEW記事）**: `#gift` セクション内のカードリスト（`space-y-12`）の先頭または末尾に、横長 `<article>` カードを追加する。
- **パターンB（DATE記事）**: `#date` セクション内の `grid grid-cols-1 md:grid-cols-3 gap-6` 内に、正方形（`aspect-square`）オーバーレイ `<a>` カードを追加する。
  - サムネイルにはステップ2.3で生成した1:1画像（例: `yokohama.jpg`）を指定する。
  - ※すでに同一記事へのカードが `index.html` に存在する場合は重複追加しない。

## ステップ5: 品質セルフチェックと完了報告

ファイル作成・編集完了後、以下をスクリプト等で機械検証し、最後にユーザーへ完了報告を行う。

### 5.1 品質チェックリスト（`GEMINI.md` セクション6準拠）
1. **HTML構文チェック**: `<header>`, `<h1>`, `<main>`, `<div>`, `<footer>`, `<a>` 等の開閉タグに不整合・重複・ネスト誤りがないか。
2. **固有メタ情報**: `<title>` と `<meta name="description">` が新記事の内容になっているか。
3. **リンク・ボタン検証**:
   - 楽天アフィリエイトURLは、その施設・商品そのものの専用ページがある場合のみ変換して使用し、周辺検索結果・宿一覧ページ（`yado/spot` 等）になっていないか。
   - CTAボタンのテキストがすべて `この施設の詳細を見る`（または `この商品の詳細を見る`）で統一され、色がすべて黒（`bg-black hover:bg-gray-800`、赤色分岐なし）になっているか。
   - 外部リンクに `target="_blank"` が付いているか。
4. **画像・メディア検証**:
   - 指定したすべての画像ファイル（記事内画像 + `index.html` サムネイル）がルート直下に実在し、リンク切れがないか。
   - 各画像が目視確認済みで、施設の外観・全体像が一目で分かる映える構図になっているか（デッキの一部・看板・判別困難な遠景になっていないか）。
   - ライセンス上必要なクレジット表記が抜け漏れていないか。
   - Instagram埋め込みやYouTube埋め込み、`instagram.com/embed.js` 等が残っていないか。
5. **アニメーションJS**: `.reveal` クラスを使用している場合、末尾のスクロール監視 `<script>` が正しく含まれているか。

### 5.2 ユーザーへの完了報告フォーマット
チェック完了後、以下の情報を簡潔に報告する。
1. **変更・作成ファイル一覧**: 新規記事HTMLファイル、`index.html` 更新有無、保存した画像ファイル一覧
2. **採用したメディアとライセンス表記**: 各スポット・サムネイルのWikimedia Commons元ファイル名・著者・ライセンス（またはGoogleマップ/楽天画像フォールバック箇所）
3. **設定したCTAリンク一覧（1位〜N位）**: 使用した楽天アフィリエイトID、変換前URLと変換済みアフィリエイトURL（楽天不在枠は公式サイトURL）
